## Internationalization (i18n)
The internationalization module provides centralized multilingual support for the Angular application. It allows components to load only the translation resources they require and dynamically switch the application language at runtime. The internationalization system based on `Angular Signals` and feature-scoped `JSON` translation files. Translations are loaded lazily and cached in memory, allowing runtime language switching without unnecessary network requests.

**Components**
- `TranslationService` - manages language state, loads JSON translations per feature scope, and provides translation lookup `API`
- `TranslatePipe` - template pipe for easy key-based translations in `HTML` 
- Language state (signal-based) - reactive global language switching (`en` / `uk` / `pl`). The language can be changed using: `setLang(lang: Lang)`
- Translation `Scopes` - translations are divided into scopes instead of loading one large translation file for the entire application. 
- Feature-based `JSON` structure - translations split by scope (e.g. `home`, `about-popup`).
- Lazy loading mechanism - loads translations only when a specific scope is needed.
- Caching layer - stores loaded translations per language and scope to avoid duplicate requests.

**Components request translation scopes; `TranslationService` manages translation resources; `TranslatePipe` provides translated values to templates.**

<pre>
Component
     │
     ▼
TranslationService.load(scope)
     │
     ▼
assets/i18n/<scope>/<lang>.json
     │
     ▼
Cached in Signals
     │
     ▼
TranslatePipe / t(scope, key)
     │
     ▼
Rendered template
</pre>

### TranslationService
Global service built with `Angular Signals`. `Lazily loads` feature-scoped `JSON` translation files, caches translations per language and scope, and provides reactive runtime language switching through the `t(scope, key)` API.

**Responsibilities:**
- Manages the active application language.
- Stores the currently selected language using an `Angular Signal`.
- Lazily loads translation files on demand.
- Keeps track of already loaded translation `scopes`.
- Caches previously loaded translations to avoid redundant `HTTP` requests.
- Provides reactive translation updates using `Angular Signals`.
- Exposes a simple `t(scope, key)` method for retrieving localized strings.

---

### TranslatePipe
Provides a simple way to access translations directly from Angular templates.

Usage:
<pre>
{{ 'LOGIN' | t:'forms/login-form' }}
</pre>

The pipe receives:
`key` — translation key.
`scope` — translation scope.

It delegates the actual lookup to `TranslationService`.
